# PPT Agent MVP 分阶段开发任务清单

> 历史实施计划。2026-08-19 起，检查/交付门禁与前端流转以 [`../业务场景需求.md`](../业务场景需求.md) 和产品契约第 0 节为准。

> 配套基线：《PPT Agent MVP 产品需求与流程契约》  
> 用途：供数字员工按阶段设计、实现、联调和验收 MVP；本文规定实施顺序、任务边界和完成证据，不替代产品契约。  
> 原则：如本文与产品契约冲突，以产品契约为准；实现细节未确定时，先补 ADR/机器契约，不得自行改变产品行为。

## 1. 执行规则

### 1.1 每个数字员工开始任务前必须读取

1. 产品需求与流程契约；
2. 本任务清单中当前任务、直接依赖和阶段门禁；
3. 仓库 README、现有约定及与当前任务有关的 Skill；
4. 已合入的机器契约、ADR 和测试夹具。

### 1.2 单个任务的交付格式

每个任务提交时必须包含：

- `任务 ID` 与对应契约章节；
- 实际修改范围和未修改范围；
- 代码、迁移/示例数据、测试和必要文档；
- 执行过的验证命令及结果；
- 已知限制、后续依赖和兼容性影响；
- 可供下游消费的稳定接口或产物路径。

不得仅以“页面可打开”“接口返回 200”或“模型调用成功”作为完成依据。每项验收必须验证业务状态、版本关系、门禁和失败行为。

### 1.3 并行与合并纪律

- `P0` 必须串行完成；`P1` 的契约任务完成后，后端、前端壳和测试夹具可并行；
- 同一状态模型、版本模型和文件布局只能有一个权威定义；其他任务引用它，不复制定义；
- UI 可用 mock gateway 开发，Agent 流程可用 fake model/renderer 开发；真实模型接入不得阻塞确定性流程测试；
- 每阶段只在门禁验收通过后进入下一阶段；发现契约缺口先记录 ADR，再继续实现；
- 禁止顺带实现 PDF/PPTX、移动端、统一主 Agent、截图视觉检查等非 MVP 能力。

## 2. 总体阶段与关键路径

| 阶段 | 目标 | 关键输出 | 可并行情况 | 退出门禁 |
|---|---|---|---|---|
| P0 基线与仓库勘察 | 固定现状和实现边界 | 技术现状报告、ADR 清单、验收映射 | 低 | 技术边界无歧义 |
| P1 机器契约与运行内核 | 建立唯一事实源 | Schema、FSM、工作区、事件/版本协议 | 中 | 契约测试通过 |
| P2 任务输入与澄清 | 打通任务创建到可规划输入 | 输入快照、资源清单、问答集 | 前后端可并行 | 阻断/默认/冻结可验证 |
| P3 叙事与逐页大纲 | 形成 HTML 的权威内容输入 | 两类版本化 Markdown | 中 | 编辑、重生成、确认闭环 |
| P4 样品页闭环 | 锁定视觉方向 | 真实 HTML 样品、确认事实 | 中 | 未确认不可生成全稿 |
| P5 全稿与局部修改 | 生成并可控修改整稿 | 完整 HTML、影响域、版本关系 | 中 | 页数、范围和版本一致 |
| P6 检查与人工审核 | 建立独立质检闭环 | 报告、修复轮次、处置记录 | 中 | 阻断问题受控 |
| P7 交付与恢复 | 完成可追溯交付 | 交付包、结果摘要、恢复能力 | 中 | 仅明确确认后完成 |
| P8 联调与 MVP 验收 | 证明产品闭环 | E2E、验收报告、运行文档 | 高 | 18 条验收全部有证据 |

关键路径：`P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8`。阶段内部标注为可并行的任务可以并发，但必须共同通过阶段门禁。

## 3. P0：基线、勘察与实现决策

### P0-01 仓库与现有能力盘点

- 依赖：无。
- 工作：盘点前后端入口、存储、模型调用、HTML 预览、测试、配置、现有 Image Agent 可复用边界；记录缺口，不改产品需求。
- 产物：`docs/current-state.md`，含目录图、运行命令、可复用模块、技术债和风险。
- 验收：新员工可依据文档启动项目；所有“已有/缺失”结论有文件或命令证据。

### P0-02 建立需求—实现—测试追踪矩阵

- 依赖：P0-01。
- 工作：将产品契约第 14 节 18 条验收标准映射到本清单任务、接口/页面和 E2E 用例 ID。
- 产物：`docs/acceptance-matrix.md`。
- 验收：18 条无遗漏，每条都有负责人任务和最终测试证据位置。

### P0-03 决策记录与非目标护栏

- 依赖：P0-01。
- 工作：为运行方式、持久化、任务工作区、模型网关、HTML 沙箱/预览、版本策略建立最小 ADR；列明 MVP 非目标。
- 产物：`docs/adr/`。
- 验收：后续任务无需猜测核心技术边界；ADR 不擅自改变产品契约。

**P0 门禁**：仓库能在本地按文档启动；验收矩阵完整；核心技术决策均有 ADR 或明确留待 P1 定义。

## 4. P1：机器契约与可恢复运行内核

### P1-01 定义领域 Schema

- 依赖：P0。
- 工作：定义并版本化 `TaskCard`、`TaskInputSnapshot`、`ResourceManifest`、`ClarificationSet`、`NarrativeDocument`、`SlideOutline`、`SampleSelection`、`DeckArtifact`、`InspectionReport`、`IssueDisposition`、`DeliveryManifest`。
- 要求：严格校验未知字段；稳定 ID；时间、版本、hash、来源和引用语义明确；Markdown 与 JSON 任务卡归一化到同一模型。
- 验收：合法/非法 fixture、向后兼容策略和 JSON Schema 导出测试通过。
- 契约映射：第 4、7、8、9、12 节。

### P1-02 定义唯一状态机与门禁矩阵

- 依赖：P1-01。
- 工作：实现业务阶段与正交运行状态；覆盖 `waiting_for_user`、running、paused、cancelled、failed、completed；定义 manual/auto 转移规则和所有门禁。
- 验收：非法迁移被拒绝；等待人工不变成 failed；生成全稿/检查通过不产生 completed；模式切换只影响后续动作。
- 契约映射：第 6、10、13 节。

### P1-03 工作区、版本与内容寻址产物

- 依赖：P1-01。
- 工作：为每个任务建立隔离目录；保存输入快照、资源 manifest、Markdown、HTML、检查报告、事件和交付物；写入采用原子提交；产物具有 hash。
- 验收：并发写不产生半文件；历史版本不可被覆盖；重启可读取最后成功状态；跨任务资源不可误读。
- 契约映射：第 4.2、4.4、9、10.3 节。

### P1-04 命令处理器与事件审计骨架

- 依赖：P1-02、P1-03。
- 工作：统一实现“校验命令→读取权威状态→执行窄动作→保存产物→保存版本/checkpoint→迁移状态→发布可展示事件”；失败不得推进成功指针。
- 验收：重复命令幂等；中断后恢复；事件足以解释状态但不包含模型思维过程或敏感凭证。

### P1-05 Gateway 协议与测试替身

- 依赖：P1-01。
- 工作：定义生成模型、检查模型、Skill 加载器、HTML 构建器和文件存储协议；提供 deterministic fake；记录模型配置和 Skill 版本快照。
- 验收：不访问真实模型即可跑完整状态测试；检查模型调用入口与生成模型上下文隔离。
- 契约映射：第 3.4、5、12.1 节。

### P1-06 后端 API 与错误模型

- 依赖：P1-01～P1-05。
- 工作：定义任务查询、动作提交、版本读取/对比、预览、问题处置、暂停/取消和事件/进度查询接口；错误对用户可理解，同时保留内部诊断 ID。
- 验收：OpenAPI/等价接口文档、示例和契约测试齐全；接口不泄露推理文本和供应商原始异常。

**P1 门禁**：Schema、状态机、持久化和 API 契约测试全部通过；用 fake gateway 可从空任务推进到一个模拟交付状态，且所有人工门禁不可绕过。

## 5. P2：任务创建、资源扫描与澄清

### P2-01 Markdown/JSON 任务卡导入与归一化

- 依赖：P1。
- 工作：支持两种格式；校验演示目标、受众、核心主题；展示约束、默认值和假设。
- 验收：同义输入形成等价快照；阻断缺失进入 `waiting_for_user`；非阻断缺失可见且可修改。

### P2-02 授权资源扫描与 manifest

- 依赖：P1-03。
- 工作：仅扫描当前任务目录；关联图片与配套 Markdown；检测缺失、重复、无效引用；不要求模型看图。
- 验收：无图片仍可继续；越权路径、目录穿越和损坏引用被阻止；资源 hash 固定。

### P2-03 输入冻结与资料变更规则

- 依赖：P2-01、P2-02。
- 工作：创建不可变输入快照；独立模式仅在大纲确认前允许显式重建快照；启动后上游新增资源不静默纳入。
- 验收：冻结后新增文件不会改变当前 manifest；采用新资源必须产生新快照/版本和清晰记录。

### P2-04 澄清问题生成与回答

- 依赖：P2-01、P1-05。
- 工作：只生成影响路径、事实或关键交付的问题；选择题含 `Other`；保存问题、选项、回答和假设；支持改答后使下游失效。
- 验收：重复恢复不重复提问；修改回答会标记相关后续产物过期，而非静默覆盖。

### P2-05 “任务/资料”桌面端页面

- 依赖：P1-06；可与 P2-01～04 并行。
- 工作：创建/导入任务，展示资源、默认值、阻断项、问答和当前主操作；尚未到达阶段显示前置条件。
- 验收：键盘和常见桌面分辨率可完成任务创建与回答；运行状态和等待原因清晰；不显示内部推理。

**P2 门禁**：任务卡、资源、冻结、缺失处理和澄清在 API 与 UI 两层闭环；形成可复现的 `TaskInputSnapshot + ResourceManifest + ClarificationSet`。

## 6. P3：叙事结构与逐页大纲

### P3-01 分阶段 Skill 装载

- 依赖：P1-05、P2。
- 工作：为叙事、大纲动作只加载所需 Skill 片段；记录版本/hash 和裁剪结果，禁止把所有 Skill 一次注入。
- 验收：相同快照、Skill 版本和模型配置可追溯；不同动作的上下文边界有测试。

### P3-02 叙事结构生成、编辑与版本

- 依赖：P3-01。
- 工作：生成核心结论、叙事路径、章节组织；支持直接编辑、Prompt 修改、局部/整体重生成、增删调序。
- 验收：直接编辑成为权威版本且不被静默改写；每次动作形成新版本；未指定章节保持 hash 不变。

### P3-03 逐页大纲生成与资源引用

- 依赖：P3-02。
- 工作：依据确认叙事生成逐页 Markdown；遵守强页数；使用 Markdown 资源引用；验证页面 ID、顺序和资源存在性。
- 验收：生成页数和约束一致；引用均来自冻结 manifest；可无图片生成待补资源位。

### P3-04 大纲局部操作与影响域

- 依赖：P3-03。
- 工作：页/章节级重生成、增删、调序、Prompt 修改；计算受影响页；下游 HTML 存在时标记对应范围过期。
- 验收：局部修改不改变无关页面；潜在跨页影响先展示；回退不删除历史。

### P3-05 大纲工作区 UI

- 依赖：P1-06；可与 P3-02～04 并行。
- 工作：叙事与逐页大纲双视图；Markdown 直编与 Prompt；版本摘要、影响范围、确认/重开入口。
- 验收：manual 未确认不能进入样品；auto 可自动推进到大纲完成但仍保留可见版本；大纲阶段不生成视觉预览。

**P3 门禁**：两类 Markdown 均版本化、可编辑、可回退；逐页大纲成为 HTML 唯一权威内容输入；manual 门禁和 auto 推进符合矩阵。

## 7. P4：HTML 样品页闭环

### P4-01 样品页推荐与选择

- 依赖：P3。
- 工作：推荐代表视觉风格和主要版式的页面；默认 2 页；允许 1 页到全稿；保存选择依据和页面 ID。
- 验收：用户可在生成前调整；无效或重复页面被拒绝。

### P4-02 HTML 生成协议与安全预览

- 依赖：P1-05、P4-01。
- 工作：根据确认大纲和真实资源生成可播放 HTML；资源路径可移植；建立预览隔离、内容安全和错误诊断。
- 验收：无占位文本/占位图；画布比例正确；任务外资源不可访问；构建失败保留最后成功产物。

### P4-03 样品修改与作用域识别

- 依赖：P4-02。
- 工作：结合选中页面/元素和 Prompt 判断范围；显示理解结果；仅在明显歧义时追问；记录全局规则与局部特例。
- 验收：元素、页面、全局三类修改均有用例；局部特例不会自动泛化；修改形成新版本和摘要。

### P4-04 样品预览与确认 UI

- 依赖：P4-02；可与 P4-03 并行。
- 工作：真实 HTML 预览、页/元素选择、Prompt 面板、版本对比、确认按钮。
- 验收：manual/auto 都必须由用户点击“确认样品并生成全稿”；未确认时 API 与 UI 均不能绕过。

**P4 门禁**：真实样品可反复修改；确认事实绑定具体大纲版本、样品版本和 hash；任何模式都不能自动越过样品确认。

## 8. P5：完整 HTML、影响域与版本一致性

### P5-01 全稿生成

- 依赖：P4 门禁。
- 工作：一次生成全部剩余页面；纳入确认样品并默认保持不变；建立页 ID 到大纲条目、HTML 片段、资源的映射。
- 验收：页数与最终大纲一致；确认样品 hash 未被无提示改变；完整 HTML 可独立播放。

### P5-02 内容修改与视觉修改分流

- 依赖：P5-01。
- 工作：内容/叙事修改先产生大纲新版本再更新 HTML；纯视觉修改只产生 HTML 新版本；记录对应关系。
- 验收：两类修改均有状态和版本测试；大纲—HTML 不一致时明确标记，不静默修复。

### P5-03 局部重生成与未指定范围保护

- 依赖：P5-01。
- 工作：支持元素、页、多页、整稿修改；计算依赖闭包；只重建受影响范围并执行必要整稿一致性处理。
- 验收：无关页面的规范化 hash 不变；跨页变化必须出现在影响摘要中。

### P5-04 版本对比与非破坏回退

- 依赖：P5-01。
- 工作：时间线展示来源、操作者、摘要和大纲/HTML 关系；回退通过复制历史版本形成新当前版本。
- 验收：历史永不删除；可预览/对比；回退大纲导致不一致时提示重新生成范围。

### P5-05 全稿与版本 UI

- 依赖：P5-01；可与 P5-02～04 并行。
- 工作：整稿播放、页/元素定位、Prompt 修改、差异摘要、版本时间线、失败恢复选项。
- 验收：进入工作区自动定位当前阶段、待办和最新产物；失败不清空成果；不展示原始技术栈。

**P5 门禁**：全稿页数、资源、样品、大纲关系一致；局部修改隔离与非破坏回退有自动化证据。

## 9. P6：独立检查、自动修复与人工审核

### P6-01 独立检查输入隔离

- 依赖：P5。
- 工作：检查 Gateway 仅接收“最初大纲 + 待审 HTML”；不继承生成对话、自述、图片或截图；输出严格结构化报告。
- 验收：测试证明禁止字段未进入请求；报告包含严重度、层级、页面/元素范围、证据和建议。

### P6-02 三级检查与增量检查策略

- 依赖：P6-01。
- 工作：覆盖元素、页面、整稿三级规则；首次全检；修改后检查影响范围并补充必要整稿一致性检查。
- 验收：每个层级有 fixture；报告绑定 HTML hash；旧报告不能误用于新版本。

### P6-03 manual/auto 修复编排

- 依赖：P6-02。
- 工作：manual 只提交建议；auto 在最大轮数内修复—复检；人工明确意图优先；达到上限停止并等待人工。
- 验收：轮数准确、不可无限重试；达上限不标记通过/完成；模式中途切换只影响下一动作。

### P6-04 问题处置与阻断门禁

- 依赖：P6-02。
- 工作：支持 Agent 修复、手工处理、接受/豁免、暂不处理及同类批量操作；保存 actor、时间、依据和目标版本。
- 验收：未解决且未豁免的阻断问题禁止交付；普通警告可附说明交付；新 HTML 版本使相关处置重新评估。

### P6-05 检查与审核 UI

- 依赖：P6-01；可与 P6-03～04 并行。
- 工作：按严重度和页面分组；联动预览；展示修复轮次、遗留问题和操作入口；整稿人工浏览无需逐页打勾。
- 验收：批量操作范围明确；阻断门禁在 UI 和 API 双重生效；等待人工有原因和直达入口。

**P6 门禁**：检查与生成上下文隔离；manual/auto 行为、最大轮数和阻断处置均被自动化测试覆盖。

## 10. P7：交付、暂停取消与恢复

### P7-01 明确交付命令与不可绕过门禁

- 依赖：P6。
- 工作：只有用户对具体候选版本执行“确认完成/交付”才创建交付事实并转为 completed。
- 验收：全稿生成、检查通过、文件存在均不能隐式完成；确认绑定版本/hash、actor、时间和问题摘要。

### P7-02 交付包与结果摘要

- 依赖：P7-01。
- 工作：打包完整 HTML、资源、最终叙事 Markdown、最终逐页大纲、资源清单、版本/状态摘要和结果说明；预留未来主 Agent 回传结构。
- 验收：交付包可在干净目录运行；manifest 校验全部 hash；不含完整内部日志、推理或未授权文件。

### P7-03 交付后派生新候选

- 依赖：P7-01。
- 工作：从已交付版本继续修改时保留原交付，形成新候选；重新检查并再次确认后才产生新交付。
- 验收：旧交付不可变且可预览；新候选不会覆盖旧 manifest。

### P7-04 暂停、取消、失败与进程恢复

- 依赖：P1-04、P5。
- 工作：停止启动新动作，让当前原子动作安全收尾；保存最后成功版本；提供重试、修改输入或人工处理；重启恢复。
- 验收：在生成、持久化、检查各断点注入故障；无半提交、无无限重试、无成功指针误推进。

### P7-05 状态摘要与未来编排适配器

- 依赖：P7-02。
- 工作：输出规范阶段、进度、当前动作、等待原因、人工事项、最新产物和错误摘要；定义未来 pause/cancel/result 接口，但不实现统一主系统。
- 验收：摘要不含推理/完整对话；一项主任务只对应一个 PPT 工作区；资源集合保持启动快照语义。

**P7 门禁**：交付包完整可运行；completed 只有一条合法路径；暂停/取消/故障恢复不破坏最后成功版本。

## 11. P8：联调、质量与发布验收

### P8-01 契约测试与 Golden Fixtures

- 依赖：P1～P7。
- 工作：覆盖 Schema、FSM、API、版本、检查报告、交付 manifest；固定正常、缺失、损坏、旧版本兼容 fixtures。
- 验收：CI 稳定、无真实模型依赖、失败可定位到契约条款。

### P8-02 端到端场景

- 依赖：P8-01。
- 至少覆盖：
  1. Markdown 任务卡 + 有图片资源 + manual 完整交付；
  2. JSON 任务卡 + 无图片 + auto 修复后交付；
  3. 阻断输入补齐；
  4. 样品未确认时阻止全稿；
  5. 大纲局部修改仅更新受影响页；
  6. auto 达最大轮数转人工；
  7. 阻断问题豁免后交付；
  8. 中断恢复与非破坏回退；
  9. 已交付版本派生新候选并再次交付。
- 验收：每个场景产生可查状态、版本、事件和文件证据。

### P8-03 桌面端体验验收

- 依赖：P8-02。
- 工作：验证固定阶段导航、当前主操作、Markdown 编辑、HTML 预览、元素选择、问题定位、版本对比和错误恢复。
- 验收：目标桌面浏览器和分辨率清单通过；空态、加载、等待、失败、只读历史版本均有明确呈现。

### P8-04 安全与数据边界检查

- 依赖：P8-02。
- 工作：任务隔离、路径穿越、HTML 预览隔离、Prompt/日志敏感信息、资源授权、文件类型/大小限制、模型超时与未知结果。
- 验收：高风险项有测试或明确风险接受；密钥、原始异常和内部推理不进入 UI/交付包。

### P8-05 可观测性与运行手册

- 依赖：P7、P8-02。
- 工作：结构化日志、诊断 ID、动作耗时/失败/修复轮次指标、备份恢复和常见故障手册；不记录思维链。
- 验收：操作人员可定位失败动作并安全恢复；文档包含开发、测试、配置和本地演示命令。

### P8-06 最终验收矩阵回填

- 依赖：P8-01～05。
- 工作：逐条回填产品契约第 14 节的测试 ID、录屏/截图或产物路径、结论和遗留限制。
- 验收：18 条全部通过；未通过项不得以“后续优化”替代 MVP 必须项。

**P8 门禁**：验收矩阵全绿，关键 E2E 可重复运行，交付与恢复演示完成，MVP 非目标未被误纳入完成标准。

## 12. 建议的数字员工任务分工

以下是职责轨道，不要求对应固定人数：

| 轨道 | 主责 | 最早启动点 | 不可越界 |
|---|---|---|---|
| 契约/架构 | P0、P1、跨阶段 ADR | 立即 | 不替产品方新增流程 |
| 后端流程 | Handler、FSM、版本、API、交付 | P1 Schema 稳定后 | 不在 handler 内复制状态机 |
| Agent/Prompt | Skill 装载、生成/检查 gateway、影响域 | P1 Gateway 稳定后 | 不持有项目唯一事实源 |
| 前端工作区 | 阶段视图、编辑、预览、审核、版本 | P1 API 草案稳定后 | 不仅靠前端实现门禁 |
| 测试/QA | fixtures、契约、E2E、安全、矩阵 | P0-02 后持续 | 不依赖真实模型产生确定性结论 |

建议每个阶段由“实现员工”和“验收员工”分离：实现员工提交代码与自测；验收员工依据契约和矩阵复核，不以实现说明代替证据。

## 13. 首批可创建的工程任务

为避免一开始拆得过细，先创建以下首批任务，完成 P1 评审后再按稳定接口释放 P2～P8：

1. `P0-01` 仓库与运行现状盘点；
2. `P0-02` 18 条验收追踪矩阵；
3. `P0-03` 核心 ADR 与 MVP 非目标；
4. `P1-01` 领域 Schema 与 fixtures；
5. `P1-02` 状态机和门禁矩阵；
6. `P1-03` 工作区、版本和产物存储；
7. `P1-05` Gateway 协议及 deterministic fake；
8. `P1-06` API 草案与前后端评审；
9. `P1-GATE` P1 集成门禁验收。

`P1-GATE` 通过后，可并行释放 P2 后端、P2 前端、P3 Skill/Agent、前端工作区壳和持续 QA 五条工作流。

## 14. 完成定义（Definition of Done）

一个开发任务只有同时满足以下条件才可标记完成：

- 行为符合产品契约，并注明对应章节；
- 依赖的机器契约未被私自绕开或复制；
- 正常、边界、失败和恢复路径有相称测试；
- 用户可见文案不泄露内部推理、原始异常、UUID 或供应商细节；
- 状态、版本、产物和审计事实保持一致；
- 文档、示例和下游接口同步更新；
- 验收矩阵已回填；
- 未把 MVP 非目标作为隐含依赖。

整个 MVP 只有在产品契约第 14 节 18 条验收标准全部获得可重复证据，并且用户能够在桌面工作区完成“任务创建 → 澄清 → 叙事 → 大纲 → 样品确认 → 全稿 → 检查/处置 → 明确交付”的完整闭环后，才算完成。
