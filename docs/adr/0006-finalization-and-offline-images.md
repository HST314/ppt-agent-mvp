# ADR-0006：终稿事实与图片离线本地化

## 状态

状态：已采纳
日期：2026-08-19

## 决策

把“用户确定终稿”和“写入离线交付包”拆成两个独立动作。终稿以不可变 `final-deck` 版本绑定当前 `deck_hash`，同时记录检查状态和遗留问题计数；检查不再是终稿或交付门禁。离线写包由 `delivery.publish` 持久化 Job 执行，成功原子发布并校验后才把任务标记为完成。

HTML 预览允许受限 HTTP(S)、Base64 与任务内相对图片。交付时远程图片必须经过 SSRF、重定向、类型、签名、数量和大小限制后下载，相对图片必须通过冻结 manifest/hash 校验后复制，所有引用改写为包内路径；离线扫描仍拒绝外部运行时 URL。

## 理由

终稿是用户的内容决策，检查是可选的质量信息，文件写入则是可能失败且耗时的工程动作。拆分三者可清楚表达状态、支持恢复与重试，并避免把“检查通过”或“目录存在”误报为完成。图片本地化兼顾在线预览的灵活性和最终交付的可复现性。

## 后果

- 用户可以快速从全稿直接交付，也可以进入完整自检修改闭环。
- 任何交付均能追溯到精确终稿 hash 和当时的检查状态。
- 远程资源失败不会污染已成功版本或产生半交付目录。
- 历史 `delivery/confirm` 端点保留为兼容包装，但新 UI 使用终稿与发布两个显式端点。
