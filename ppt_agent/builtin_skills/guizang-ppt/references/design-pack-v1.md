# Guizang PPT Design Pack v1

本文件是样品与全稿阶段的轻量、版本化设计上下文。它只描述生成单页
`section.slide` 所需的常用约束；公共 HTML 外壳由服务端统一组装。

## 固定输出

- 只生成请求中列出的 slide_id，顺序必须完全一致。
- 每页必须是一个完整的 `<section class="slide" id="slide-N" data-slide-id="slide-N">…</section>`。
- 不输出 `html`、`head`、`body`、`style`、`script`、iframe 或远程 URL。
- 内容必须忠于逐页大纲；不可新增未给出的事实、资源 URI 或页面。
- 所有文字与图形必须留在 1280×720 画布内，正文优先保证可读性。

## 常用布局

1. 标题页：左侧标题与一句结论，右侧使用简单几何视觉或已授权资源。
2. 结论页：顶部短标题，下方 2–4 个并列结论卡片。
3. 对比页：左右两栏，使用相同层级和对齐基线，不用表格堆字。
4. 流程页：3–5 个等宽步骤，使用数字与连线表达顺序。
5. 数据页：一个主数字或主图形配 2–3 条解释，避免装饰性图表。

## 主题与排版

- 使用统一深色或浅色主题，不在同一批次混用视觉语言。
- 标题建议 40–56px，正文建议 22–30px，辅助文字不得低于 16px。
- 正文行高至少 1.35；同页最多两种字重、三层文字层级。
- 保持高对比度；不要用仅靠颜色区分状态的表达。
- 使用 CSS 基础形状和清晰边框；禁止 emoji 充当图标。

## 组件规则

- 卡片：同一页圆角、边框、阴影保持一致，卡片间距至少 20px。
- 列表：每项尽量一行，最多 5 项；长段落改写为短句而非缩小字号。
- 图片：仅使用输入中已授权的 data URI；必须有非空 alt，使用 object-fit 避免变形。
- 标识：可用 `data-element-id` 标记可编辑元素，ID 在页面内保持唯一。

## 提交前检查

- 页面数量、顺序和 slide_id 与请求完全一致。
- 无裁切、重叠、横向溢出、远程资源、脚本或未授权内容。
- 每页都有明确视觉焦点，标题和核心结论能在数秒内识别。
- 直接提交最终 JSON；除非确实缺少布局规则，不要请求读取更多文件。
